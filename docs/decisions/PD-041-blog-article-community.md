# PD-041 — ArticleDetail community stays product-local

- **Status:** accepted validation / defer extraction
- **Owner:** Blog public product-local / Core validation
- **Evidence:** the real `gouno-blog` `/articles/:slug` community tail combines a reversible like state, signed-in and guest comment composition, one-level replies, empty discussion, non-fatal interaction failure, report reason collection and a report confirmation lifecycle. The migrated Showcase fixture preserves these behaviors as local state only; it performs no real comment, identity or report request.
- **Decision:** keep the community state machine product-local. Canonical Core `Button`, `Badge`, `Card`, `Empty`, `Field`, `Input`, `Textarea`, `Alert` and `Modal` already express the stable control, validation, feedback and dialog contracts. Blog continues to own like count/state, `aria-pressed` product semantics, signed-in-vs-guest author policy, comment identity/content, reply topology, report target/reason and success/error lifecycle.
- **Abstraction impact:** do **not** admit `CommentThread`, `CommentComposer`, `LikeButton`, `ReportDialog`, `CommunityPanel`, a Community Pattern or a broader Reading Pattern from this single public content product. Same-product repetition is evidence to watch, not sufficient ownership proof.
- **API impact:** none. No Core, Pattern, Theme or Gouno public API changes and no new runtime dependencies.
- **Accessibility impact:** the like control exposes `aria-pressed`; form errors flow through canonical `Field` error wiring; report uses canonical Modal title/description/actions; replies remain one level deep so the fixture does not invent an unproven recursive discussion contract.
- **Failure/fixture impact:** `signed-in`, `guest`, `empty` and `error` modes exercise the major presentations. Empty discussions can gain their first local comment. Interaction failure is non-fatal and does not replace the article reading surface.
- **Validation:** focused product tests cover reversible like count/state, root reply publication, the no-reply-on-reply rule, guest nickname/content validation, first comment from empty state, required report reason + modal close/success feedback, non-fatal error presentation, ArticleDetail integration, absence of Pattern/Gouno imports, absence of real network calls and absence of raised/overlay/modal elevation leakage in product composition.
- **Follow-up:** continue the Blog public migration with account/custom-page families. Revisit a community abstraction only if an independently owned product proves a smaller semantically equivalent interaction contract.
